# 移动端搜索信息架构方案

状态：**已实现方案 B（产品默认）** · 方案 A 仅保留设计稿  
更新：2026-08-14（实现已在 `main`；下文 §2「现状」是 8 月 12 日选型时的代码，不要当现在的 SkinHead 行为）  
依据：Cursor 计划 M-2 · 用户反馈 · 执行侧评审 · 用户确认「按执行建议：B」

现行行为：`≤720px` 头部是 brand · 🔍 · 主题；点 🔍 打开 `SearchOverlay`（焦点陷阱、`visualViewport`、草稿与已提交 query 不一致时不展示旧结果）。桌面仍是常驻 `SearchBar`。详见 [STATUS.md](./STATUS.md)。

**可点对比原型（并排 A / B，A 作对照）**  
→ [`docs/mockups/m2-search-compare.html`](./mockups/m2-search-compare.html)

**产品决策**
- 手机 ≤720px：**B** — `brand | 🔍 | 主题` + 全屏搜索层；tab 去掉「搜索」
- 桌面：头部常驻 `SearchBar` + 6 tab 不变
- **不**做主题切换 A/B；A 不进双轨运行时

---

## 1. 问题定义

| 来源 | 主张 |
|------|------|
| **Cursor 计划（M-2）** | 搜索框必须常驻头部；手机被压到 24–47px 是布局 bug → 改两行 head（brand+tools / 整宽 search），目标 `searchW ≥ 0.6×vw`、头高 ≤112px |
| **用户** | 默认不搜时，全局放搜索框没必要；需要搜时再放到合适位置 |
| **执行侧** | 已有「搜索」tab + 头部 `SearchBar` **双入口**；常驻框与 M-3「首屏多露列表」抢垂直空间；样稿两行 head 是「必须常驻」前提下的补丁，不是最优 IA |

根因不是「框不够宽」，而是 **窄屏下把搜索当成全局 chrome**，与「多数时间在逛榜/库/词」的用法不匹配。

---

## 2. 现状（代码事实）

- 头部：`SkinHead` 始终渲染 `<SearchBar className="skin-search" />`（`layouts/shared.tsx`）
- Tab：已有 `search`；结果列表在 `tab === "search"` 时渲染
- 离开搜索 tab 时 `setTab` **清空 `searchQuery` 字符串**，但 **保留 `searchResults`**（设计已偏向「搜是一种模式，不是全局滤镜」）
- 桌面宽屏：一行 brand | search | tools 仍合理

---

## 3. 方案结论（推荐）

### 原则

> **默认不占坑；进入搜索上下文再给满宽输入。**  
> 不是取消搜索，而是 **按场景披露**。

### 分端策略：**A — 窄屏渐进披露 / 宽屏可常驻**

| 视口 | 头部 | 搜索输入出现位置 |
|------|------|------------------|
| **≤720px（手机 / 窄屏）** | **无**整行搜索框；可选 **🔍 图标**（点一下 → `setTab("search")` + focus） | **仅**在「搜索」tab 面板 **顶部** 满宽 `SearchBar`（列表上方） |
| **>720px（桌面）** | 保持现有全局 `SearchBar`（效率；快捷键路径短） | 提交后仍切到 / 停在搜索 tab 展示结果（与现逻辑一致） |

不推荐全端都去掉头部搜索（桌面多点一次 tab，收益小）。  
不推荐继续把 M-2 做成「两行常驻搜索」作为终态（修了宽度，浪费一截列表高度）。

### 入口（窄屏，三选一都可点到同一状态）

1. Tab「搜索」  
2. 头部 🔍（可选但建议保留，降低「只有 tab 里才有搜」的发现成本）  
3. 空态 CTA（如热榜空 / F-4「去搜索」）→ `setTab("search")` + focus  

进入后统一状态：`tab === "search"`，面板顶满宽输入，下方结果列表。

### 窄屏头部默认形态

```
[ 品牌 ]                    [ 🔍? ] [ 主题 ]
[ Tab 行：搜索 | 热榜 | … ]   ← 已有，可横滚
[ 内容区 / 列表 ]
```

- 工具区继续收：语言进主题面板（M-2 原建议保留）  
- **不做**「brand+tools / 第二行整宽 search」作为默认  

### 交互细节

| 项 | 行为 |
|----|------|
| 提交搜索 | 已有 `search(q)`；确保在搜索 tab；结果列表更新 |
| 离开搜索 tab | 保持：清输入展示用的 query，**保留 results**（回来还能看上次结果） |
| 再进搜索 tab | 输入框空或回填上次 query 二选一：**建议空 + 下方仍显示上次 results**，避免误以为在搜新词；或「输入框回填 + 可一键清空」（F-10a 一起做） |
| 键盘 /a11y | 桌面 `/` 或现有快捷键若有 → 聚焦搜索；窄屏 🔍 与 tab 都有 `aria-label` |
| 字号 | 搜索面板内 input ≥16px（并入 M-5，不必单独常驻头） |

## 4. 与原计划条目的关系

| 编号 | 原计划 | 本方案下的调整 |
|------|--------|----------------|
| **M-2** | 两行 head 撑开常驻框 | **改写目标**：窄屏默认 **不渲染** 头部 `SearchBar`；搜索 tab 内满宽；验收改为「非 search tab 无 `.skin-head .skin-search`；search tab 内 input 宽 ≥ vw−32」 |
| **M-3** | 压播放器腾列表 | **受益**：少一行 head，rowsVisible 更容易 ≥3 |
| **M-样稿** | 已做两行 search | 视为中间态；按本方案 **改一版样稿** 再合 main |
| **M-5** | 全局 input 16px | 主要覆盖 **搜索面板** + 主题筛选，不再依赖头内框 |
| **M-10** | tab 可读性 | 「搜索」入口更关键；图标+≥2 字 |
| **F-10a** | 搜索历史 | 做在 **搜索面板内**，不做在全局头 |
| **F-7** | 键盘全流程 | 「🔍 或 tab → 输入 → 播放」 |

P0 / P1 / 其它 M 项不变。

## 5. 实现切片（确认后执行，仍一条一条）

建议拆 **1 个 commit**（或 2 个：IA 移动 + 桌面保留回归）：

1. `SkinHead`：宽屏渲染 `SearchBar`；窄屏用 CSS 隐藏 **或** 条件渲染 + 可选 🔍  
   - 条件渲染更干净（不占 a11y 树）；断点与 `matchMedia` / CSS 二选一，优先 **CSS 隐藏桌面框 + 面板内始终挂一份** 易出双框，故推荐：  
   - **一份 SearchBar**：窄屏 portal/移到 panel top；或  
   - **两处 DOM**：头（仅 `min-width: 721px` 显示）+ 面板顶（仅 `max-width: 720px` 且 `tab===search` 显示）——实现简单，注意不要两处同时可 focus  
2. `usePanelBody` 或 Search 专用壳：search tab 顶部插 `SearchBar`  
3. 可选：`skin-head` 🔍 → `setTab("search")` + `requestAnimationFrame` focus input  
4. 更新 M-2 验收脚本字段；改 `OPTIMIZATION-PLAN` / `GROK-RUNBOOK` M-2 文案与 tracker  
5. 回归：桌面头搜仍可用；窄屏热榜首屏无搜索行；进搜索可搜可播  

**不做本轮**：搜索建议 API、虚拟键盘避让大改（可记 F）。

## 6. 验收标准（替换原 M-2 数字）

**窄屏 390 / 320**

1. `tab !== "search"`：`.skin-head` 内 **无** 可见搜索 input（或宽度 0 / 不存在）  
2. `tab === "search"`：搜索 input 宽度 ≥ `innerWidth - 32`；字号 ≥16px（可与 M-5 同验）  
3. 热榜 tab：`rowsVisible` 不低于改前样稿，且 **不因搜索行变差**（目标仍 ≥3，宜更好）  
4. 点 tab「搜索」或 🔍 → 输入框可聚焦、可提交、结果列表更新  

**桌面 1440**

5. 头部仍有可用搜索框；提交后结果在搜索上下文可见  

**工程**

6. `typecheck` + `test` 绿；涉及客户端则 `build`  

---

## 7. 不采纳的备选（及原因）

| 备选 | 原因 |
|------|------|
| 终态坚持 M-2 两行常驻 | 与用户目标、M-3 列表高度冲突 |
| 全端取消头搜、只留 tab | 桌面变差，收益有限 |
| 全局 overlay 搜索（Command palette 风） | 实现与主题成本高，本 app 有 tab 已够 |
| 每个 tab 顶都挂搜索 | 又变相全局常驻 |
