M-2 搜索 · 双方案设计对比

仅设计稿 / 可点原型，不改业务代码。手机框约 320×680（对应 390 逻辑的紧凑示意）。 两套都解决「默认别占坑」；差异在搜索打开后的形态与是否保留搜索 tab。

方案 A 旧：搜索 tab 内顶栏输入 方案 B 新：头部 🔍 + 全屏层（不盖迷你条） 点状态按钮或手机内控件切换

方案 A Tab 内搜索（旧方案）

窄屏头部去掉常驻 SearchBar；保留 tab「搜索」。 只有进入该 tab 时，在列表面板顶部出现满宽输入。桌面仍可常驻头搜（本稿只画手机）。

测量：—
结构
  • Head：brand | 主题（无搜索框）
  • Tabs：仍 6 项，含「搜索」
  • 仅 search tab：面板顶 SearchBar 满宽
  • 结果：同一 tab 下方 TrackList
利
  • 改动小，复用现有 tab + search() 语义
  • 与 locate → tab search 自然一致
  • 无 overlay / history / visualViewport 复杂度
弊
  • 搜索仍占一个 tab 名额（6 项挤）
  • 从热榜去搜：先点「搜索」再输入，两步
  • 没有独立「取消回原 tab」；靠再点别的 tab
  • 最近搜索要塞进 tab 内容区，形态弱于层

方案 B 🔍 + 全屏层（本方案）

头部 brand | 🔍 | 主题；tab 去掉「搜索」（5 项）。 点 🔍 打开层（盖列表、露出迷你条）；取消 / 返回键关闭并回到进入前 tab。

弊
  • 实现重：visualViewport、pushState、手势内 focus
  • 要小心不破坏 search() 的 tab:"search" 与 locate
  • 一层组件 + portal，测试面更大
